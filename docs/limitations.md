# 已知限制与未来扩展建议

## 1. 已知限制

### 平台限制

- **iOS**：自动化只能按发件人或关键词触发，不能转发「所有短信」；无法读取第三方 App 的通知；运行受专注模式、低电量模式、锁屏策略影响。详见 [iphone-shortcuts.md](iphone-shortcuts.md)。
- **Telegram**：Bot 不能主动联系从未点过「开始」的用户；单条消息最长 4096 字符（超长消息自动拆分为多条，标注 1/3、2/3……）；同一聊天约每秒 1 条（网关自动排队）。
- **Bot 聊天不是端到端加密的**，消息会保存在 Telegram 服务器上。

### 投递语义

- 采用**至少一次**投递：网络中断导致结果不确定时会重发，**可能出现重复消息**（会被标记为「结果不确定」）。Telegram Bot API 没有幂等机制，无法做到精确一次。
- 重试最长 24 小时（可配置），之后放弃并标记为失败 / 不确定，正文随即删除。
- 投递按顺序逐条进行（单个工作协程）。对个人使用足够；Telegram 长时间限流时，后面的消息会等待。
- 已拆分的长消息若中途失败，重试从未发送的部分继续；若程序升级导致拆分结果变化，则从头重发。

### 状态与监控

- **来源没有心跳**：只能知道「最近一次收到消息的时间」，不能判断设备是否在线；长时间无消息不代表故障。
- **外部可达性无法自测**：服务器无法从外部探测自己是否可访问，「消息接入」的外部可达性以真实请求为准。
- **Telegram 故障时，Bot 无法报告 Telegram 故障**：需要借助 `/healthz` 外部监控或 SSH。
- CPU 使用率是查询时约 0.3 秒的采样，不保存历史，没有趋势图。
- 服务器指标读自 `/proc`，反映的是整台宿主机；网关自身只显示内存占用。
- 「最近错误」列表只保存在内存中（最多 20 条），重启后清空；投递记录本身保存在数据库中。

### 功能范围

- 只支持文本消息；不支持图片、文件、语音。
- 只有一个输出目标（一个 Telegram 聊天），所有来源都发到这里；路由规则需要改代码。
- 新增来源、轮换凭证需要在服务器上使用命令行；Bot 中只能停用 / 启用来源。
- 管理员只有一个级别，没有细分权限；增加管理员需要修改配置并重启。
- HTTP 管理接口只读。
- 服务直接暴露在公网，不读取 `X-Forwarded-For`。若放到 Cloudflare / nginx 之后，IP 限流会把所有请求视为同一 IP，需要改造。
- 部署方式为 systemd（按约定未使用 Docker）；仓库中没有 Dockerfile。

### 短信过滤

- AI 分类会出错，重要短信可能被判为广告（可在 Bot 中 7 天内找回），广告也可能漏网。
- 除验证码外的短信会在遮盖数字和链接后发给 DeepSeek，文字内容仍会离开服务器。
- 验证码识别靠关键词，没有关键词的验证码短信会被遮盖后交给 DeepSeek；含验证码字样的广告会被直接转发。
- 详见 [sms-filter.md](sms-filter.md)。

### 未经真机验证的部分

- iPhone 快捷指令的具体操作步骤（菜单名称、变量属性）未在真机上逐步验证，因为开发环境无法操作 iPhone。服务端接口已用真实 HTTPS 请求测试。
- 长时间（数天以上）运行的稳定性和内存表现，只做了短时间测量。

## 2. 未来扩展建议

按投入产出比排序：

1. **外部存活监控**：用 UptimeRobot 等免费服务每 5 分钟访问 `/healthz`，在 Telegram 之外获得告警。无需改代码。
2. **主动异常通知**：投递持续失败、证书即将过期、磁盘不足时，由 Bot 主动发一条提醒（需注意 Telegram 本身故障时无法通知）。
3. **更多来源**：Android（Tasker / HTTP Shortcuts）、Linux cron、Windows 计划任务等只需创建来源并发送 HTTP 请求，无需改代码。示例见 [adding-sources.md](adding-sources.md)。
4. **路由规则**：在 `router` 中实现按来源 / 类型 / 优先级的规则（例如某来源静音、`alert` 类型同时发到第二个聊天），再从配置文件加载规则。
5. **多个输出目标**：实现新的 `delivery.Channel`（例如 Bark、ntfy、邮件），每条消息可对应多个目标，现有数据模型已支持（一条消息多条投递记录）。
6. **Bot 内的更多管理操作**：暂停 / 恢复全部通知、修改来源名称、查看最近错误详情。新增按钮动作只需在 `bot.dispatch` 中添加。
7. **多管理员与只读成员**：将管理员列表移入数据库，区分「可查看」和「可操作」。
8. **附件支持**：图片 / 文件需要 multipart 上传与临时存储，并重新评估隐私与磁盘占用。
9. **本地关键词规则**：在 DeepSeek 之前加入发件人 / 关键词黑白名单，命中的短信不必调用 AI。
