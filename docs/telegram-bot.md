# Telegram Bot 配置教程与菜单说明

Telegram Bot 在本项目中有两个角色：

1. **通知出口**：各来源的消息由它推送到你的 Telegram。
2. **管理入口**：你可以在私聊中通过按钮菜单查看网关、Bot、服务器的运行状态，并停用 / 启用消息来源。

---

## 一、配置教程

### 1. 创建 Bot

1. 在 Telegram 中搜索 **@BotFather**（认准蓝色认证标记），发送 `/newbot`。
2. 按提示输入 Bot 的显示名称（例如 `我的消息网关`）和用户名（必须以 `bot` 结尾，例如 `my_nekopost_bot`）。
3. BotFather 返回一串 Token，形如 `1234567890:AAH...`。**这串 Token 等同于 Bot 的密码，不要发给任何人。**

建议同时在 BotFather 中设置：

- `/setjoingroups` → `Disable`：禁止把 Bot 拉进群组（网关本身也会忽略群组消息，这是双重保护）。
- `/setprivacy` → `Enable`（默认值）。

### 2. 获取你的 Telegram 用户 ID

管理员身份按**数字用户 ID** 识别，不按用户名或昵称（这两者可以随意修改，容易被冒充）。

获取方法（任选其一）：

- 在 Telegram 中给 **@userinfobot** 发任意消息，它会回复你的 `Id`。
- 网关启动后，用一个**未授权**账号给你的 Bot 发消息，Bot 会回复该账号的用户 ID。

### 3. 写入服务器配置

```bash
sudo nano /etc/nekopost/nekopost.env
```

填写：

```ini
NEKOPOST_TELEGRAM_BOT_TOKEN=1234567890:AAH...
NEKOPOST_TELEGRAM_ADMIN_IDS=你的数字ID
```

多个管理员用逗号分隔：`NEKOPOST_TELEGRAM_ADMIN_IDS=111111,222222`。消息默认投递到第一个管理员的私聊；如需投递到其他聊天，设置 `NEKOPOST_TELEGRAM_CHAT_ID`。

### 4. 对 Bot 点击「开始」

Telegram 规定：**Bot 不能主动给从未与它对话过的用户发消息**。所以在 Telegram 中打开你的 Bot，点击「开始 / Start」（或发送 `/start`）。

### 5. 重启并检查

```bash
sudo systemctl restart nekopost
sudo nekopost check --send-test
```

`check` 会检查配置、数据库和 Telegram 连接；`--send-test` 会向投递目标发一条测试消息。全部显示 `✓` 即配置成功。

## 二、菜单与交互

### 转发的消息

转发来的消息正文只有内容。下方并排两个按钮，分别显示来源和类型（含分类），点击后会弹出这条消息的详情（接收时间、设备时间、投递状态、消息 ID），消息本身不会变化。格式见 [message-model.md](message-model.md#在-telegram-中的呈现)。

### 管理菜单

在与 Bot 的私聊中发送 `/start` 或 `/menu` 打开主菜单。所有页面都用按钮操作，点击后**原地更新同一条消息**，不会刷屏。

```
📋 消息网关 · 主菜单
整体状态：🟢 正常运行

[🏠 系统总览] [🤖 机器人状态]
[🖥 服务器状态] [📨 消息来源]
[📊 消息统计] [⚙️ 系统设置]
[🗑 已过滤] [❓ 帮助]
```

「🗑 已过滤」只在启用[短信过滤](sms-filter.md)时出现。

每个页面底部都有 **🕒 数据更新于 HH:MM:SS**，表示页面内容是在那个时刻读取的快照；点 **🔄 刷新** 获取最新数据。

### 状态图例

| 图标 | 含义 |
|---|---|
| 🟢 正常 | 有证据表明工作正常（例如最近一次投递成功） |
| 🟡 部分异常 | 功能可用但有问题（例如投递失败正在重试、消息积压） |
| 🟠 配置错误 | 需要人工修正配置（例如 Token 无效、Bot 被屏蔽） |
| 🔴 不可用 | 功能当前无法工作（例如 Telegram 不可达） |
| ⚪ 无法确认 | **没有证据**判断好坏（例如启动后还没有投递过消息）。网关不会把「未知」当成「正常」 |

### 🏠 系统总览

列出六个组件各自的状态，以及今日的接收 / 送达 / 失败 / 处理中数量：

- **消息网关服务**：进程、数据库、投递队列处理是否正常。
- **消息接入**：HTTPS 接口是否在监听、证书是否有效；以及「最近一次有效提交」时间。服务器无法主动探测外部可达性，所以外部可达性以真实请求为准。
- **Telegram 转发**：最近一次投递的结果，以及待处理队列。
- **管理 Bot**：长轮询是否在正常与 Telegram 通信。
- **消息来源**：启用数量，以及是否有来源使用了已吊销的凭证。
- **服务器资源**：内存、磁盘、负载是否在安全范围。

这几项相互独立，例如可能出现「消息接入正常，但 Telegram 不可达」「转发正常，但管理 Bot 配置冲突」等组合。

如果 Bot 超过 3 分钟没有与 Telegram 通信，页面会提示「以上信息可能不是最新状态」。

### 🤖 机器人状态

- 总体状态：正常运行 / 部分功能异常 / Telegram 服务不可达 / 配置错误 / 状态暂时无法确认。
- Bot 身份（用户名与 ID）。
- 管理功能（长轮询）与消息转发两条通道分别的状态。
- 最近成功发送、最近发送失败的时间。
- 最近 5 次投递结果（只显示时间、来源和结果，**不显示正文**）。
- 已知问题列表、本次启动后的最近错误、未授权访问次数。

注意：「Bot 能回复你」只说明管理通道正常；转发是否正常要看「消息转发」一行。启动后还没有投递过任何消息时，会显示「尚无投递记录，转发功能未经验证」。

### 🖥 服务器状态

分两部分：

- **宿主机**：运行时间、CPU（约 0.3 秒采样的瞬时值）、负载、内存、Swap、磁盘。
- **消息网关服务**：状态、启动时间、版本、自身内存占用、累计启动次数、上次启动时间。

读取失败的指标显示「不可用」。不保存任何历史数据，只有在你打开此页面时才采集，不会持续消耗资源。

### 📨 消息来源

列出所有来源：启用状态、最近消息时间与结果、今日接收 / 失败数量。点击来源名称进入详情页，可以：

- **⏸ 停用此来源**：先显示确认页，点「确认停用」后才生效（确认 5 分钟内有效）。停用后该来源的新提交会被拒绝（HTTP 403），已在队列中的消息仍会投递。
- **▶️ 启用此来源**：同样需要确认。

> 「最近消息」只表示最近一次收到该来源的消息。来源没有心跳或主动健康检查，**长时间没有消息不代表故障**。

### 📊 消息统计

可切换 **今天 / 24 小时 / 7 天 / 启动以来**，显示：接收、成功送达、投递失败、结果不确定、处理中、重复提交（已忽略）、各来源数量、最近消息时间。

- 「接收」= 服务器已接受的消息；「送达」= Telegram 已确认收到。这是两个不同阶段。
- 每条消息只计一次；重复提交单独计数，不计入接收。
- 统计基于保留期（默认 30 天）内的元数据。

### 🗑 已过滤

列出被短信过滤判定为广告、垃圾或漫游提醒、没有推送的短信（保留 7 天），每页 8 条，显示时间、来源、类别、发送方和正文摘要。点 **↩️ 转发 N** 把误判的第 N 条正常转发出来。这是管理菜单中唯一显示消息正文的页面。详见 [sms-filter.md](sms-filter.md#5-在-telegram-中查看和找回)。

### ⚙️ 系统设置

只读显示当前配置概况：版本、接入地址、证书有效期、时区、投递目标（ID 部分隐藏）、投递策略、去重策略、限流、隐私策略、管理员数量、来源数量。

Bot 内可执行的管理操作只有「停用 / 启用来源」和「转发被过滤的短信」。新增来源、轮换凭证、修改配置需要在服务器上执行（见 [deployment.md](deployment.md)）。**Bot 不提供执行服务器命令、修改文件或操作系统服务的功能。**

### 命令列表

| 命令 | 作用 |
|---|---|
| `/start` | 欢迎信息 + 主菜单 |
| `/menu` | 主菜单 |
| `/status` | 系统总览 |
| `/bot` | 机器人状态 |
| `/server` | 服务器状态 |
| `/sources` | 消息来源 |
| `/stats` | 消息统计（今天） |
| `/filtered` | 已过滤的短信 |
| `/settings` | 系统设置 |
| `/help` | 帮助 |

命令列表只对管理员显示（Bot 启动时按管理员私聊单独设置）。发送其他文字会提示「无法识别的输入」并附上主菜单。

## 三、权限与安全

- 只有 `NEKOPOST_TELEGRAM_ADMIN_IDS` 中的**数字用户 ID** 能使用菜单，用户名、昵称不参与判断。
- 只在**私聊**中响应。Bot 在群组、超级群组、频道中完全不响应（不会泄露任何信息）。
- 未授权用户发消息：Bot 回复「没有使用权限」及其用户 ID（每人每 10 分钟最多回复一次，防止被利用刷消息），不返回任何系统信息；该次访问会被计数并记录日志。
- 未授权用户点击按钮（例如转发来的旧菜单消息）：只弹出「无权限」，不执行任何操作。
- 按钮数据只能是固定的几种动作，服务器逐一解析校验，任何聊天文字都不会被当作命令执行。
- 除「🗑 已过滤」页面外，管理菜单中不显示消息正文。
- 消息投递使用的 Telegram 连接与管理菜单相同，但两者状态分别统计。

增加管理员：在 `NEKOPOST_TELEGRAM_ADMIN_IDS` 中追加 ID 后重启服务；新管理员需先对 Bot 点击「开始」。
