# Android 收件箱和设备配对

现有 Android 转发设置可继续使用。0.3 起「消息」是第一个标签页：配对后像普通收消息的软件一样看消息，不用 Telegram 也能收到通知。未配对时在「消息」或设置向导第二步选「接收消息：配对此手机」。

## 配对

新增设备不需要 SSH，三种方式任选其一，都会生成同样的五分钟配对码，审核也都是号码匹配：

1. **Telegram**：在 Bot 里打开「📱 设备」→「➕ 添加设备」（或发送 `/adddevice`），选择权限（完整 / 仅接收 / 仅转发），需要转发权限时再选来源（已有来源或「🆕 新来源」）。Bot 会发来一张二维码图片（禁止转发），以及一条文字消息，里面有服务器地址、手动配对码和完整的 `nekopost://enroll?...kind=device` 配对链接，三者都在可轻点复制的代码块里（文字消息不设禁止转发，否则无法复制）。新手机扫码即可；**如果要配对的就是正在看 Telegram 的这台手机**，复制链接或配对码，在猫邮局里点「粘贴配对链接」。配对码被使用、作废（「作废此配对码」按钮）或过期后，这两条消息会自动删除。新手机申请后，Bot 会另发一条号码匹配消息，选出手机上显示的两位数字。只有管理员能用，10 分钟内最多生成 3 个配对码；创建和作废都写入审计日志（操作者 `bot:tg:<用户 ID>`），其他管理员会收到提醒。
2. **已配对的完整权限手机**：设置 › 设备与管理 ›「添加设备」，填名称、选权限（接收消息 / 仅转发 / 完整）和来源，指纹确认（`k_reauth`，`POST /v1/admin/pairings`）后显示配对台：按住显示二维码（最长 30 秒、亮度拉满），配对码可复制，下方显示剩余有效时间和「作废配对码」（`DELETE /v1/admin/pairings/{id}`，不需要指纹）；新手机申请后在同一页选出它显示的两位数字（每次选择都要指纹）。桌面模式下二维码在上半屏。
3. **服务器终端**（仍然可用）：

```bash
sudo nekopost device pair --name Fold8 --role full --source fold8
```

需要发送权限的配对应绑定正确的来源 ID。同一服务器、同一来源的既有转发配置在配对后可使用设备签名认证。扫码、粘贴配对链接，或手动填写地址及配对码，核对服务器域名，再在 Telegram、管理手机或服务器终端选出手机显示的两位数字。不要把配对码转发给别人，也不要把凭证或消息正文发到聊天里。Bot 发出的配对消息禁止转发，并在用过或过期后删除。

「仅接收」角色使用 `--role receiver`。「仅转发」使用 `--role sender`。Nekopost 使用 Android Keystore 中的 P-256 设备密钥。另一把需要强生物识别的密钥用于管理操作，因此配对前请先在设备设置系统屏幕锁和强生物识别。

## 应用锁

打开应用（冷启动）或从后台回来时整个应用都要验证身份：指纹或手机自己的锁屏密码 / 图案（`BiometricPrompt` `BIOMETRIC_STRONG | DEVICE_CREDENTIAL`，没有单独的密码）。配对或登记后默认开启，设置 › 应用锁可以关闭（关闭需要先验证一次）。

- 离开应用后：立即 / 30 秒（默认）/ 1 分钟 / 5 分钟；关闭屏幕总是立即锁定。
- 无操作自动锁定：1 / 5（默认）/ 15 分钟 / 从不。值守台常亮时也照常计时。
- 合上手机时（折叠屏）：遮挡内容（默认，轻点后验证）/ 锁定应用 / 不处理。
- 应用自己打开的界面不会触发锁定，也不会丢结果：二维码扫描、指纹 / 锁屏验证、权限对话框、系统设置页（电池、通知使用权、屏幕锁）、分享面板、旁边窗口。每种有期限（扫码 5 分钟，系统设置 3 分钟，权限、验证和分享 2 分钟），超过期限回来仍会锁定。值守台常亮时无操作计时照常进行，到时间整个应用锁定。扫码结果保存在进程里，锁着也不会丢，解锁后交给发起扫码的页面。
- 锁定时界面内容保留（输入到一半的配对码、向导步骤、选中的消息都在），只是不绘制、不可访问。
- 手机没有设置屏幕锁时应用锁无法生效：不会把人锁在外面，设置页和首页顶部会提示去设置。

## 消息

- 列表：头像（来源图标或首字）、发件人、时间、一行预览、未读圆点；验证码消息有「验证码」小按钮，一按就复制（敏感剪贴板，60 秒后自动清除）。顶部搜索（输入时先在已加载的消息里筛，按搜索键查全部）、全部 / 未读 / 验证码筛选，下拉刷新，滚动自动加载更多。
- 详情：发件人、来源、时间、验证码大卡片（复制按钮；封面屏轻点即复制、长按拖到其他应用），正文可选中复制，底部显示投递回执和正文删除日期。打开 1 秒自动标为已读并清除通知；菜单里可标为未读、复制正文、在旁边打开。
- 内屏左右分栏，封面屏单栏；桌面模式消息在上半屏、列表在下半屏，筛选栏旁有值守台和分拣台。
- 分拣台、值守台、发给自己、键盘快捷键在右上角「⋮」菜单里；设备配对、解除配对和设备管理都在设置里。

## 通知

- 每条消息一条通知：标题是发件人，正文是预览；验证码消息正文是「验证码 123456」，带「复制验证码」（需要手机已解锁）和「标为已读」按钮。多条时合并成「N 条新消息」。
- 锁屏只显示「猫邮局 · 1 条新消息 / 1 条验证码」，不含发件人、正文或验证码（`VISIBILITY_PRIVATE` + 公共版本）；是否隐藏还取决于系统「锁定屏幕 › 隐藏敏感内容」。
- 点通知直接打开那条消息（解锁后）。在本机或其他设备读过、正文过期或被删除的消息，通知自动消失。
- 设置 › 消息通知 可以只显示「来源 · 类别」，并查看推送状态、发送测试推送（管理手机）和服务器的 Telegram 投递范围。
- 通知通道：验证码（高优先级）、消息、低优先级消息、系统。

从通知直接复制验证码不经过应用锁，但要求手机本身已解锁（`setAuthenticationRequired`），这是为了「一键复制」的有意取舍。

## 只用 App 接收（不用 Telegram）

`NEKOPOST_TELEGRAM_TYPES` 决定哪些消息类型发到 Telegram（`*` 为全部，默认；`none` 为都不发；或用逗号分隔的类型，如 `sms`）。Telegram 不接收的类型由 App 推送作为主通道：推送被 FCM 接受即算送达（`已推送到 App`），失败会按退避重试最长 24 小时。设备自己的推送设置（类型、最低优先级、类别）排除的消息记为 `skipped`，不算失败；转发这条短信的手机本身默认不重复推送。都没有可推送设备时状态是 `not_routed`，但只要服务器保留正文（`NEKOPOST_BODY_RETENTION_DAYS` > 0），消息仍可在 App 收件箱里看到。Bot 不受影响，继续用于管理和审批。`GET /v1/devices/self` 的 `telegram_types`（`null` = 全部）告诉 App 哪些类型只通过 App 接收。

## FCM

按 [V2 设计](v2/design.md) §14.1 创建 Firebase 项目、正式 Android 应用和服务账号。正式包名是 `com.drinkcat.nekopost`。备份正式签名密钥，并在仓库配置下列 **variables**：

- `FIREBASE_PROJECT_ID`
- `FIREBASE_APP_ID`
- `FIREBASE_API_KEY`
- `FIREBASE_SENDER_ID`

服务器使用 `nekopost-fcm-sa` systemd 加密凭证，或 `NEKOPOST_FCM_CREDENTIALS_FILE` 所指定的服务账号文件。把内容放进系统凭证，保持服务账号 JSON 与 APK 签名私钥在仓库之外。

未配置 FCM 时可以手动刷新和在前台通过事件流接收更新。配对后才启用 Firebase Messaging。FCM 数据载荷只包含消息 ID、序号及协议类型，从不包含正文：

| `t` | 其他字段 | 含义 |
|---|---|---|
| `msg` | `id`、`seq` | 新消息。App 用 `GET /v1/inbox/{id}?via=push&ack=1` 取详情并确认收到（审计为 `message.push_fetch`，不算查看） |
| `read` | `ids`（逗号分隔，最多 50 个） | 消息已在其他设备标为已读，清除对应通知（NORMAL 优先级，ttl 1 小时） |
| `gone` | `ids` | 消息已删除或正文已销毁，清除对应通知 |
| `ping` | — | 测试推送 |
| `revoked` | — | 设备已吊销 |

Android 发出的本地通知在锁屏中只显示公共版本；正文经设备验证后在收件箱读取。

收件箱列表、搜索和同步条目另有：`sender`（未打码的标题：短信号码或「应用名 · 标题」，最多 64 字；正文过期时为 `null`；紧跟验证码关键词的验证码总是遮盖；`has_code` 的消息还会遮盖标题里任何位置像验证码的片段，只有短信的纯号码标题保持原样）、`app_only`、`deliveries[].aux`。`GET /v1/inbox` 返回 `unread_count`，并支持 `?unread=1`、`?has_code=1` 过滤。`title`、`preview` 仍然打码，保持兼容。

## 真机验收

1. 保留旧 App 数据安装同签名的新 APK。确认原短信及通知转发工作，然后完成设备配对。
2. 在电脑和手机上确认新设备可读消息。测试冷启动和回到前台的应用锁、扫码配对途中不被锁定、闲置锁、搜索、到期正文和前台事件更新。
3. 发送测试推送，再从另一个来源提交普通消息和一条带验证码的短信。检查通知标题是发件人、验证码可从通知复制、锁屏只显示通用提示；点通知解锁后直接打开那条消息，并核对网页投递回执。在网页上标为已读，手机上的通知应消失。
4. 在掉线后恢复网络，检查收件箱和通知。操作自己的设备前，用测试设备演练暂停读取、吊销和重新配对。
5. 走完[折叠屏验收](foldables.md)。

正式 APK 由 `app-v*` 标签构建，需要事先配置 Android 签名 secrets。除非另有显式授权，工作分支的 CI 仅生成验证产物。
