# 短信过滤（DeepSeek）

开启后，网关在转发短信前先用 DeepSeek 给短信分类。广告、垃圾信息和出国时的漫游 / 海关提醒等不推送到 Telegram，但会保留几天，可以在 Bot 里找回。代码位置：`internal/filter`。

## 1. 处理流程

```
iPhone ──▶ 服务器接收并保存（status = classifying，iPhone 立即得到回应）
              │
              ▼
        是验证码类短信？ ──是──▶ 分类为「验证码」，直接转发（不调用 DeepSeek）
              │否
              ▼
        遮盖数字和链接 ──▶ DeepSeek 分类
              │
      ┌───────┴────────────────────────┐
      ▼                                ▼
 漫游提醒 / 广告营销 / 垃圾诈骗      其他类别，或 DeepSeek 出错 / 超时
 status = filtered                    正常转发，消息下方的按钮标注类别
 不推送，正文保留 7 天                 例如 [📱 iPhone] [💬 短信 · 快递/出行]
 可在 Bot「🗑 已过滤」中找回
```

- 只处理 `type` 为 `sms` 的消息（`MSGGW_FILTER_TYPES`），其他类型照常转发。
- 分类在后台进行，不会让 iPhone 端的请求变慢。快捷指令使用 `?wait=8` 时，等待期间可能先看到「已接收，正在识别是否为广告」，然后才是最终结果。
- **DeepSeek 出任何问题都直接转发**，包括超时（15 秒）、网络错误、Key 无效、余额不足、返回内容无法识别。如果连续失败 3 次，接下来 5 分钟内不再调用 DeepSeek，短信直接转发，避免每条都等到超时。
- 服务在分类过程中重启时，这条短信保持「待分类」状态，重启后重新分类，不会丢失。

## 2. 分类

| 类别 | 显示 | 默认处理 |
|---|---|---|
| `code` | 验证码 | 转发（由本地规则识别，不经过 DeepSeek） |
| `finance` | 银行/支付 | 转发 |
| `logistics` | 快递/出行 | 转发 |
| `personal` | 个人 | 转发 |
| `service` | 通知 | 转发（DeepSeek 无法确定时也归入此类） |
| `roaming` | 漫游/出入境提醒 | **不推送**。到达其他国家时运营商发的欢迎、漫游资费、海关申报须知、外交部 / 使领馆安全提醒等。漫游期间的余额不足、流量用尽等具体账户提醒不算此类 |
| `marketing` | 广告营销 | **不推送** |
| `spam` | 垃圾/诈骗 | **不推送** |

提示词要求：同一条短信里既有交易或账户信息又有推广内容时（例如账单短信末尾附带广告），按交易或账户信息归类，**不算广告**。

## 3. 隐私

- **验证码类短信不会发给 DeepSeek。** 只要短信里出现「验证码、校验码、动态密码、取件码、認証コード、verification code、OTP」等字样，服务器本地就判定为验证码并直接转发。这条规则宁可多判：广告被误判成验证码，最多就是被转发出来。
- **其余短信发送前做遮盖**：连续 3 位及以上的数字（卡号、金额、电话、单号）替换为 `#`，链接替换为 `[链接]`。例如：
  `尾号6789的卡消费1,234.56元，详情 https://bank.example.com/a` → `尾号#的卡消费1,#.56元，详情 [链接]`（1–2 位的数字保留，例如「5折」「10月25日」）
- 发给 DeepSeek 的内容包括：发送方（标题，同样遮盖）和正文前 1500 字。不会发送来源、时间、meta 等其他信息。
- DeepSeek 的服务器在中国，数据处理遵循 DeepSeek 的隐私政策。遮盖能降低风险，但无法完全消除：人名、地址、文字内容仍会被发送。
- 日志只记录消息 ID、类别、是否被过滤和耗时，不记录正文。
- 被过滤短信的正文在数据库中保留 `MSGGW_FILTER_KEEP_DAYS` 天（默认 7 天），之后由每小时运行的清理任务删除。正常转发的短信与以前一样，投递结束后立即删除。

## 4. 配置

在 `/etc/msggw/msggw.env` 中设置，然后 `sudo systemctl restart msggw`：

| 变量 | 默认值 | 说明 |
|---|---|---|
| `MSGGW_DEEPSEEK_API_KEY` | 空 | 设置后启用短信过滤；留空即关闭 |
| `MSGGW_DEEPSEEK_MODEL` | `deepseek-flash` | 使用的模型 |
| `MSGGW_DEEPSEEK_API_BASE` | `https://api.deepseek.com` | API 地址 |
| `MSGGW_FILTER_TYPES` | `sms` | 需要分类的消息类型，逗号分隔 |
| `MSGGW_FILTER_DROP` | `roaming,marketing,spam` | 不推送的类别，逗号分隔；不能包含 `code` |
| `MSGGW_FILTER_KEEP_DAYS` | `7` | 被过滤短信可以找回的天数（1–30） |

API Key 在 DeepSeek 开放平台（platform.deepseek.com）创建，需要账户里有余额。配置好后执行：

```bash
sudo msggw check
```

会用一条虚构的广告短信测试 DeepSeek，例如：

```
✓ DeepSeek 模型 deepseek-flash，测试广告短信分类为「广告营销」，用时 1.2 秒
```

关闭过滤：删除或注释 `MSGGW_DEEPSEEK_API_KEY` 后重启。重启时如果还有待分类的短信，会直接转发。

## 5. 在 Telegram 中查看和找回

- 主菜单新增 **🗑 已过滤**（命令 `/filtered`）：列出可以找回的被过滤短信，每页 8 条，显示时间、来源、类别、发送方和正文前 120 字。点 **↩️ 转发 N** 会把第 N 条按正常流程转发，通知里的类别仍显示为「广告营销」等。
- **🏠 系统总览** 显示短信过滤的状态：正常、最近调用失败（失败期间短信直接转发），或本次启动后尚未调用。
- **📊 消息统计** 显示「🗑 已过滤（未推送）」的数量。
- **⚙️ 系统设置** 显示模型、处理的类型、不推送的类别。

## 6. 对接口的影响

- 新增消息状态 `classifying`（「已接收，正在识别是否为广告」）和 `filtered`（「已过滤（不需要推送的短信），未转发」，终态）。
- 新增投递状态 `held`（等待分类）和 `filtered`。
- `GET /v1/messages/{id}` 新增 `category`、`category_text` 两个字段，未分类时为 `null`。
- `GET /v1/admin/stats` 的计数中新增 `filtered`。

## 7. 费用与限制

- 每条短信大约消耗几百个 token。按个人的短信量，费用很低，具体以 DeepSeek 官网价格为准。
- AI 分类会出错：重要短信可能被判为广告，广告也可能漏网。建议启用后的头几天多看看「🗑 已过滤」页面。如果误判较多，可以只过滤 `spam`（`MSGGW_FILTER_DROP=spam`）。
- 短信内容可能夹带「忽略以上指令」之类的提示词注入。最坏的后果是一条广告被放行，或一条短信被误过滤（仍可找回），不会影响网关的其他功能。
- 只有 `MSGGW_FILTER_TYPES` 中列出的类型会被分类。快捷指令发送短信时需要设置 `"type":"sms"`（[iphone-shortcuts.md](iphone-shortcuts.md) 中的模板已经设置）。
