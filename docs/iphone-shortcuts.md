# iPhone 快捷指令配置教程

本教程教你用 iOS 自带的「快捷指令」App 把文字或短信发到消息网关，再由网关转发到 Telegram。

整个过程只用到一个 HTTP 请求：快捷指令把 JSON 发到服务器，服务器返回一个 `message` 字段，快捷指令把它显示出来即可，**不需要在手机上做任何复杂判断**。

> ⚠️ **关于验证**：以下步骤基于 iOS 17/18 的快捷指令功能编写，服务端行为已通过自动化测试和真实 HTTPS 请求验证；但我无法在真机上操作 iPhone，**各菜单的确切名称和位置可能因 iOS 版本略有不同，请以你手机上的实际界面为准**。

---

## 0. 准备工作

在服务器上为 iPhone 创建一个消息来源（只需一次）：

```bash
sudo msggw source add iphone --name iPhone --icon 📱
```

输出类似：

```
已创建来源 iphone（📱 iPhone）

凭证（只显示这一次，请立即保存；服务器只保存其哈希）:

  mgs_xxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxx

提交地址: https://osaka.drinkcat.com/v1/messages
请求头:   Authorization: Bearer <上面的凭证>
```

记下两样东西：

| 项目 | 值 |
|---|---|
| 服务器地址 | `https://osaka.drinkcat.com/v1/messages?wait=8` |
| 凭证 | `mgs_...`（整串复制） |

`?wait=8` 表示服务器最多等 8 秒，拿到 Telegram 的投递结果后再回复，这样手机上显示的是「已送达 Telegram」而不只是「已接收」。

> 凭证丢了也没关系：执行 `sudo msggw source rotate iphone` 生成新凭证，旧凭证立即失效。

## 1. 手动发送快捷指令

用途：手动输入一段文字，或在其他 App 里「分享」文字给它，发到 Telegram。

### 1.1 创建快捷指令

打开「快捷指令」App → 右上角「＋」→ 把名称改为 **发送到 Telegram**，然后依次添加以下操作（在底部搜索框输入操作名称即可找到）：

**① 「如果」**（判断有没有分享进来的内容）

- 条件：`快捷指令输入` **有任何值**
- 在「如果」分支中添加 **「文本」**，内容为变量 `快捷指令输入`
- 在「否则」分支中添加 **「要求输入」**，提示语「要发送的内容」，输入类型「文本」
- 「结束如果」后会产生变量 **「如果结果」**

> 如果你只想手动输入，可以省略 ①，直接用「要求输入」。

**② 「词典」**（构造要发送的 JSON）

点「添加新项目」，添加以下键值（类型都选「文本」）：

| 键 | 值 |
|---|---|
| `title` | `手动发送`（可留空或删掉这一项） |
| `body` | 变量 `如果结果`（或「提供的输入」） |
| `type` | `text` |

**③ 「获取 URL 内容」**

- URL：`https://osaka.drinkcat.com/v1/messages?wait=8`
- 展开「显示更多」：
  - 方法：**POST**
  - 头部：添加一项，键 `Authorization`，值 `Bearer mgs_你的凭证`（`Bearer` 和凭证之间有一个空格）
  - 请求体：**JSON**，然后选择「文件」→ 变量 `词典`
    - 也可以不用 ② 的「词典」操作，直接在这里逐项添加 `title`、`body`、`type` 字段，效果相同。

**④ 「获取词典值」**

- 获取 **值**，键为 `message`，词典为 `URL 的内容`

**⑤ 「显示通知」**

- 内容：变量 `词典值`

完成。运行一次试试，手机上应弹出「已送达 Telegram」，Telegram 中收到一条带 📱 iPhone 标记的消息。

### 1.2 加到分享菜单（可选）

打开快捷指令详情（右下角 ⓘ）→ 打开「在共享表单中显示」，接受的类型选「文本」。之后在任何 App 中选中文字 → 分享 → 「发送到 Telegram」。

### 1.3 服务器会返回什么

服务器始终返回 JSON，其中 `message` 一定存在，可以直接显示：

| 情况 | `message` 示例 |
|---|---|
| 成功 | `已送达 Telegram` |
| 已收下但 Telegram 暂时不可用 | `投递暂未成功，正在重试`（服务器会在后台自动重试，最长 24 小时） |
| 8 秒内还没结果 | `已接收，等待投递` 或 `正在投递` |
| 重复提交 | `已送达 Telegram（重复提交，未再次转发）` |
| 凭证错误 | `提交失败：凭证缺失、无效或已吊销` |
| 来源被停用 | `提交失败：该消息来源已被停用` |
| 内容为空 | `提交失败：请求字段校验失败（body title 和 body 至少需要提供一个非空值）` |

`ok` 字段为 `true` 表示服务器已经可靠地接收并保存了消息（之后一定会尝试投递）；`delivered` 为 `true` 才表示 Telegram 已确认收到。

如果想在失败时用不同的提示音，可以在 ④ 之后加「如果 `词典值` 包含 `提交失败`」再分别显示通知。这不是必需的。

## 2. 自动转发短信（自动化）

用途：收到符合条件的短信（比如验证码、银行通知）时自动转发。

### 2.1 iOS 的实际能力与限制（务必先读）

| 能做 | 不能做 |
|---|---|
| 「信息」自动化：收到**特定发件人**或**包含特定文字**的短信 / iMessage 时触发（iOS 17 起可设置「立即运行」，无需确认） | **不能**设置成「所有短信」都触发，必须指定发件人或关键词 |
| 读取触发它的那条信息的内容和发件人 | **不能**读取第三方 App（微信、银行 App、邮件 App 等）的通知内容 |
| 在锁屏状态下运行（通常可以，但视 iOS 版本和设置而定） | 不能在后台持续运行或定时轮询短信 |
|  | 不能读取通知中心里的历史通知 |

其他需要注意的情况：

- **关键词要选准**：例如「验证码」「code」「【」（国内短信签名通常带【】）。可以为不同关键词各建一个自动化。
- **被过滤的短信**：如果开启了「过滤未知发件人」或短信被归为垃圾信息，自动化是否触发因 iOS 版本而异，请实测。
- **专注模式 / 低电量模式 / 网络不好** 时，自动化可能被延迟或失败；服务器无法知道手机没有发送。
- 本项目**不使用**任何越狱或非官方手段绕过这些限制。

> 🔐 **隐私提醒**：验证码、银行通知等敏感内容会经过你的服务器并出现在 Telegram 中。服务器在投递完成后立即删除正文，不写入日志；但 Telegram 聊天记录会保留在 Telegram 上。请为 Telegram 账号开启两步验证，并不要把 Bot 加入任何群组。

### 2.2 创建自动化

「快捷指令」App → 底部「自动化」→ 右上角「＋」（或「新建个人自动化」）→ 选择 **「信息」**：

1. **信息包含**：填关键词，例如 `验证码`；或者 **发件人**：选择联系人 / 号码。
2. 选择 **「立即运行」**（不要选「运行前确认」），可以关闭「运行时通知」。
3. 点「下一步」→「新建空白自动化」，添加以下操作：

**① 「获取 URL 内容」**

- URL：`https://osaka.drinkcat.com/v1/messages?wait=8`
- 方法：POST
- 头部：`Authorization` = `Bearer mgs_你的凭证`
- 请求体：JSON，添加字段：

| 键 | 类型 | 值 |
|---|---|---|
| `title` | 文本 | 变量 `快捷指令输入` → 点击它，选择属性 **发件人** |
| `body` | 文本 | 变量 `快捷指令输入` → 选择属性 **内容** |
| `type` | 文本 | `sms` |

> 选择变量后再点一下它，会弹出可选属性（如「内容」「发件人」）。若你的 iOS 版本没有这些属性，直接用 `快捷指令输入` 作为 `body` 即可。

**② （可选）「获取词典值」+「显示通知」**

与手动快捷指令相同。如果不想每条短信都弹通知，可以省略这一步，或只在失败时通知（「如果 `词典值` 包含 `提交失败`」→「显示通知」）。

### 2.3 可选字段

在 JSON 里还可以添加：

| 字段 | 说明 |
|---|---|
| `priority` | `high`：Telegram 中显示 ❗；`low`：静音推送 |
| `occurred_at` | 设备时间。用「当前日期」+「格式化日期」（ISO 8601）生成；仅作参考显示，服务器以自己的接收时间为准 |
| `idempotency_key` | 防重复的唯一键。快捷指令中一般不需要：服务器默认会把 60 秒内来自同一来源的相同内容视为重复 |

## 3. 测试

### 3.1 在电脑或服务器上先测

```bash
curl -sS https://osaka.drinkcat.com/v1/messages?wait=8 \
  -H "Authorization: Bearer mgs_你的凭证" \
  -H "Content-Type: application/json" \
  -d '{"title":"测试","body":"你好 こんにちは 👋\n第二行","type":"test"}'
```

返回 `"message":"已送达 Telegram"` 说明服务端一切正常，问题只可能出在手机端配置。

### 3.2 在 iPhone 上测

1. 手动运行「发送到 Telegram」，确认弹出「已送达 Telegram」。
2. 自动化：在自动化列表中点开它，可以手动运行一次测试；或者用另一部手机给自己发一条包含关键词的短信。
3. 在 Telegram Bot 中打开「📨 消息来源」，iPhone 的「最近消息」应更新为「刚刚」。

## 4. 常见问题排查

| 现象 | 可能原因与处理 |
|---|---|
| 快捷指令报「无法连接服务器」 | 手机网络问题；或服务器 443 端口不可达。用手机浏览器打开 `https://osaka.drinkcat.com/healthz`，应显示 `{"status":"ok"}` |
| `提交失败：凭证缺失、无效或已吊销` | 头部名称必须是 `Authorization`，值必须以 `Bearer ` 开头（含空格）；凭证需完整复制。若曾执行过 `rotate`，旧凭证已失效 |
| `提交失败：Content-Type 必须是…` | 「请求体」需选择 **JSON**，不要选「表单」 |
| `提交失败：请求字段校验失败（body …）` | `body` 和 `title` 都是空的：检查变量是否选对 |
| `提交失败：该消息来源已被停用` | 在 Bot 的「📨 消息来源」中重新启用，或执行 `sudo msggw source enable iphone` |
| `提交失败：认证失败次数过多` | 同一网络 10 分钟内认证失败 20 次，被暂时封禁 15 分钟。修正凭证后等待即可 |
| 显示「投递暂未成功，正在重试」 | 服务器已收下，Telegram 暂时不可用；服务器会自动重试，无需重发 |
| 自动化没有触发 | 检查关键词 / 发件人条件；确认选了「立即运行」；检查专注模式和低电量模式；被过滤的短信可能不触发 |
| Telegram 中出现两条相同消息 | 在「至少一次」策略下，网络中断时可能重复投递（宁可重复也不丢）；Bot 的状态页会将其标记为「结果不确定」 |

服务器端排查请参见 [operations.md](operations.md)。
