本文记录**实际运行**的测试和验证结果。未验证的项目在第 4 节单独列出。

测试时间：2026-10-25（东京时间）　版本：0.3.1（新增短信过滤；来源与类型改为按钮）　环境：Ubuntu 24.04，1 vCPU，955 MB 内存，Go 1.27.3

## 1. 自动化测试

```bash
make race     # go test -race -count=1 ./...
```

**结果：14 个测试包、88 个测试全部通过（开启竞态检测），`go vet` 与 `gofmt` 无告警。**

| 包 | 覆盖率 | 主要测试内容 |
|---|---|---|
| `app` | 65% | 启动整个服务 → 提交 → 送达 → 正常关闭 → 重启后数据保留；模拟「投递中崩溃」后重启自动补发并标记为不确定 |
| `httpapi` | 71% | 短信过滤端到端（广告返回 filtered 且不发 Telegram、验证码不经 AI 并在通知中标注类别、非 sms 类型不分类）；端到端提交与送达（中文 / 日文 / Emoji / 多行）；text/plain；缺失 / 错误 / 已吊销凭证、停用来源；暴力破解封禁；11 种校验错误；413 / 415 / 405 / 404；幂等键与内容去重；Telegram 故障时不报告为已送达；来源级限流且互不影响；管理 API 与来源凭证隔离；日志中不出现正文、凭证和查询参数 |
| `delivery` | 79% | 成功；429 按 retry_after 延后；5xx 标记不确定后重试；连接中断（请求已发出）标记不确定；无法连接为安全重试，错误信息不含 Token；400 永久失败；HTML 解析失败回退纯文本；403 配置错误持续重试；长消息分段中途失败后从断点续发；超过最长重试时间后放弃；唤醒与状态通知 |
| `bot` | 76% | 「已过滤」页面列出正文并可转发、重复转发被拒、非管理员无法转发、设置与总览显示过滤状态；非管理员只收到一次（限频）无权限提示且不泄露信息；群组完全静默；非管理员按钮无效；/start 菜单；9 个页面内容；旧消息无法编辑时改为新发；停用来源需确认、确认过期无效、非管理员重放无效；长轮询 offset 确认；Token 无效显示为配置错误 |
| `health` | 69% | 需求第八节的 4 种组合场景（接入正常 + Telegram 不可达、转发正常 + Bot 异常、单个来源认证失败、内存不足）；无证据时显示「无法确认」而非正常；进程 / 数据库 / 证书 / 轮询过期 / 无来源 |
| `filter` | 73% | 验证码识别（中 / 日 / 英，含不应命中的广告）；数字与链接遮盖；DeepSeek 请求格式（Key、模型、JSON 模式、关闭思考模式）；401 / 402 / 429 / 5xx / 超时 / 无法识别的回答；验证码不调用 AI；广告被过滤且正文保留；AI 故障时直接转发；连续失败 3 次后暂停调用、恢复后继续；关机时保持待分类 |
| `store` | 64% | 来源与凭证的增删改、轮换与吊销；幂等与时间窗口去重；状态流转与正文清除；崩溃恢复；统计不重复计数；被过滤消息的保留期、找回（重置重试期限）、不可重复找回；关闭过滤时放行待分类消息 |
| `render` | 92% | 转义、多语言、元数据、设备时间、未知类型、按 UTF-16 长度拆分且内容完整无乱码 |
| `config` / `auth` / `ratelimit` / `sysinfo` / `model` / `sdnotify` | 68–91% | 配置默认值与错误提示、env 文件、凭证与 HMAC、令牌桶与封禁、/proc 解析与不可用处理、ID 有序唯一、systemd 通知 |

测试使用进程内的 Telegram 模拟服务器（`internal/testutil/faketg`），不访问真实 Telegram。

### 短信过滤（0.2.0）上线情况

- 已部署：数据库从 v1 迁移到 v2（新增 `category` 列），迁移前备份到 `/var/lib/msggw/backup-before-filter.db`；服务启动正常，`/healthz` 正常。
